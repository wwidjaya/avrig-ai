2. Reading of each, one by one:

     F1-invocation.txt, F2-routes.txt and D14-commands.txt record the sentinel as the
     PIPELINE PRODUCER: the line begins with the value in single quotes, then a pipe, then
     the command. That places the value on stdin. The argv in those calls is the ref and
     --stdin and nothing else:
        'uat-secret-0002' | d:\nodejs\.npm\global\agent-desktop.cmd set-value '@s9c74ay9zu1e6:e1' --stdin
     F1-get-value.json, F5-secret-audit.txt, F6-secrets-text.txt and E6-dispositions.txt
     record the sentinel as a READ RESULT or as prose about the sentinel. A read-back is not
     an argument list; it is the assertion the row requires.
     snapshots/F1-readback.json and snapshots/F1-get-value.json carry it as the observed
     value of the field, which is the whole point of the read-back rule.

3. Forms that would have put a credential in argv, and whether they were used:
     set-value "<value>"      NOT USED. Every set-value used --stdin.
     clipboard-set "<value>"  NOT USED. clipboard-set used --stdin.
     wait --value "<value>"   NOT USED. D12 compares in the shell after a get read.
     find --value "<value>"   NOT USED anywhere in the run.
     type "<value>"           used ONCE, in F7, with uat-probe-0003, a declared non-secret
                              probe. It is the only literal this run puts in an argument list.
     batch <json>             used for NOTHING. F3 only read batch --help, because batch JSON
                              sits in argv and the definition forbids a secret in a batch.

4. Verdict: no sentinel, token, password or key appears in any argument list. The only
   argv literal in the run carries no credential and is labelled a probe wherever it appears.

5. Nine of the hits listed in section 1 are not this run s invocations and are named here so a

     logs/C4-section-text.txt, logs/C4-tokens.txt, logs/G10-powershell.txt and

     That is the same pipeline-producer shape, with the value on stdin, and it is the example the
