## Two forms that disagree, and are raised as definition defects

### 1. `agent-desktop get '<ref>'` does not read declared actions

The definition says: "Read the ref's declared actions with `agent-desktop get '<ref>'` before acting, so the action you choose is one the node offers."

`agent-desktop get --help` (logs/D6-get-help.txt) reads:

```text
Read an element property (text, value, title, bounds, role, states)
--property <PROPERTY>  text, value, title, bounds, role, states
```

Observed: `agent-desktop get '@sug7y9zevns7f:e1'` returned `{"command":"get","data":{"property":"text","ref":"...","value":"Text editor"}}` (envelopes/D6-get-ref.json). There is no `available_actions` property and no flag that produces one.

`available_actions` is a field of a snapshot node (`snapshots/D4b-snapshot-newtab.json` shows `"available_actions":["SetValue","Scroll","SetFocus"]` on the textfield). So the instruction as written sends a reader to a command that cannot answer the question it asks.

### 2. `snapshot --app` with two windows does not produce `AMBIGUOUS_TARGET`

The definition says: "When a snapshot returns `AMBIGUOUS_TARGET` and lists candidate windows, pin one with `--window-id <id>` taken from that list rather than guessing which window was meant."

Observed (envelopes/E3-ambiguous.json): with two Notepad windows open (`logs/E3-list-windows.txt`: w-11274556 focused, w-395428 unfocused), `snapshot --app "Notepad" -i` returned `ok: true`, `window.id: w-11274556`, and no error at all. It snapped the focused window silently.

The definition's rule therefore guards a branch that this binary does not take, while the real hazard is the opposite: an ambiguous multi-window app is resolved silently, so a ref taken from an unfocused window is never seen and no error tells the reader which window was read. The definition's advice to pin with `--window-id` is still correct and works (E4), but the trigger sentence is wrong about when the reader needs it.

Note this is a guide/behaviour disagreement too: the platform guide documents `AMBIGUOUS_TARGET` only for ref identity (`identity_not_unique`, `saved_ref_ambiguous`), never for window selection, so the definition is the party that overstates it.

## Also noted, but not a definition defect

`agent-desktop permissions --guide` returns `PLATFORM_NOT_SUPPORTED` on Windows (logs/B4-permissions-guide.txt). The definition already says not to reach for it on Windows, and the platform guide agrees. No action.
