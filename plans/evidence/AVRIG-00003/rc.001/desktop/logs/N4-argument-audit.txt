## Two invocations carried a fake sentinel as an argument

1. `envelopes/F7-type-headless.json`. The matrix's F7 row specifies `agent-desktop type '<ref>' "uat-secret-0002"` to prove the headless refusal. That form places the value in argv, which N4 forbids. The check cannot be run any other way as written, because the point is that the command is refused before delivery. Both rows are the matrix's, and they contradict each other.
2. `logs/F1-diag-positional.txt`. `agent-desktop set-value '@s21hsyt8z7thav:e1' "agent-desktop-uat-0001"` was run once, deliberately, to isolate the `--stdin` defect: the same act via argv returns `delivered_verified` with `post_state.value` populated, while the same act via the `.ps1` shim returns `delivered_verified` with an empty value. Without that contrast, the defect would have been indistinguishable from an application that refuses SetValue.

Both values are fakes. No real credential was ever placed in an argument list, and no credential exists anywhere in this evidence folder (logs/F5-secret-audit.txt).

**N4 verdict: FAIL by its letter, for those two recorded invocations.** The secret-path steps themselves, F1 and F2, kept the value on stdin on every route tested.
