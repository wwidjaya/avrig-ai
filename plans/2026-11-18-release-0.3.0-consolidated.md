## Goals and Objectives

1. Ship `0.3.0` from artifacts whose reported `commit_short_sha` equals the tagged commit and whose `dirty` flag is `false` on both targets, built after the version bump is committed. The 0.2.0 and 0.2.1 releases shipped `dirty: true`; this release proves the artifact before naming it.
2. Knowledge search is one endpoint, `GET` and `POST /api/v1/knowledge/search`, with a `stream` option selecting SSE or JSON, answers synthesized by `opencode/big-pickle` through `OPENCODE_API_KEY`, and the five legacy search paths returning `410 Gone`.
3. Both nodes carry the answer model through `<exec dir>/config/server.toml`, patched per target, with `/opt/avrig` staying on `127.0.0.1` and the Windows file created with an explicit loopback binding.
4. Gateway behaviour is proven, not assumed: `composync` reachable from both services, unknown prefix and unknown sub-model both `404 model_not_found`, unrelated upstream 400s stay `502 upstream_error`, and every request including streams logs provider, resolved model, status, and `elapsed_ms`.
5. `/api/v1/version` and `/api/v1/health` both report `0.3.0` with a `build` object whose `commit_short_sha` equals the deployed commit, and `avrig --verbose-version` prints the same.
6. Every console dialog is a centred modal over a dimmed backdrop with real Radix semantics, built from upstream shadcn source, and the sidebar renders with its own tokens because Tailwind now scans `packages/ui/src` and the sidebar tokens are registered.
7. The Rauthy login language control matches the landing page chip through theme tokens, deployed through `manage-rauthy` with a bumped cache-bust and a restorable previous file.
8. Sign-out confirms, clears storage, and lands on `/` on the primary path and on both fallback paths, with no `/logged-out` route, view, or navigation left behind.
9. All suites pass before the bump, `analyst` re-audits after the audit findings below are resolved, and the five source plans stay archived as superseded.

## Key Detailed Design

### Workstream A: Knowledge search

**Route surface**

```text
GET  /api/v1/knowledge/search   -> knowledge_search_get   JSON or SSE, chosen by ?stream=
POST /api/v1/knowledge/search   -> knowledge_search       JSON or SSE, chosen by body.stream

410  /api/v1/documents/search
410  /api/v1/documents/search/stream
410  /v1/documents/search
410  /v1/documents/search/stream
410  /v1/search
```

Document management stays: `/api/v1/documents/by-hash/{sha256}`, `/api/v1/documents/upload`, `/api/v1/documents/{id}/sources`.

Tombstones are mandatory because `web.rs:22-32` serves `index.html` with `200` for any unknown dotless path. One handler, registered on all five paths with `axum::routing::any`:

```rust
async fn search_endpoint_moved() -> (StatusCode, axum::Json<serde_json::Value>) {
    (
        StatusCode::GONE,
        axum::Json(serde_json::json!({
            "error": "This search endpoint was removed. Use /api/v1/knowledge/search; pass stream: true or Accept: text/event-stream for SSE."
        })),
    )
}
```

**Request contract**

| Field | Type | Default | Notes |
| :--- | :--- | :--- | :--- |
| `query` | string | required | `q` or `query` on GET; existing validation unchanged |
| `limit` | integer | 5 | 1..=MAX_SEARCH_LIMIT |
| `threshold` | float | falls back to `server.search_threshold` | unchanged |
| `stream` | bool, optional | absent | `Some(true)` SSE, `Some(false)` JSON, absent negotiates on `Accept` |

```rust
fn resolve_stream(requested: Option<bool>, headers: &HeaderMap) -> bool {
    requested.unwrap_or_else(|| {
        headers
            .get(header::ACCEPT)
            .and_then(|v| v.to_str().ok())
            .is_some_and(|v| v.to_ascii_lowercase().contains("text/event-stream"))
    })
}
```

**Handler decomposition.** `execute_search` (`main.rs:2352-2414`) and `execute_search_stream` (`:2515-2673`) duplicate auth, embed, retrieve, rerank, and rank. Collapse to one core plus two renderers:

```text
struct SearchOutcome { query: String, count: usize, reranked: bool, results: Vec<SearchHit> }

retrieve_search(&AppState, &HeaderMap, &SearchRequest) -> Result<SearchOutcome, (StatusCode, String)>
render_json(SearchOutcome) -> Response
render_sse(AppState, SearchOutcome) -> Response

knowledge_search(State, HeaderMap, Json<SearchRequest>) -> Result<Response, (StatusCode, String)>
knowledge_search_get(State, HeaderMap, Query<SearchQueryParams>) -> Result<Response, (StatusCode, String)>
```

`render_sse` destructures `SearchOutcome` by value so `results` moves into `SseCitations` after metadata serializes. `state.gateway.clone()` and `state.answer_model` are read before the `async_stream` block.

**Test-update scope, measured not estimated.** `main.rs` contains 22 direct handler call sites and 19 `SearchRequest { ... }` literals. Adding `stream: Option<bool>` without a `Default` impl breaks every literal, so all 19 gain `stream: None` or an explicit value, and the two stream tests at `:4552` and `:4593` are retargeted to `knowledge_search` with `stream: Some(true)`. The route-table test at `:4622-4706` currently registers the five legacy routes and asserts `500`; it inverts to `410`.

**Answer model resolution**

```text
model string        opencode/big-pickle
provider prefix     opencode  (registered direct provider, case-insensitive)
base model          big-pickle (forwarded upstream unchanged)
upstream            POST https://opencode.ai/inference/openai/v1/chat/completions
auth                Authorization: Bearer $OPENCODE_API_KEY
precedence          registered direct provider wins over Antigravity
validation          GET {base_url}/models; big-pickle present, so it passes
missing API key     dispatch fails, SSE emits the existing fallback delta
```

No `avrig-lib` resolver change: `opencode` is a builtin prefix and the direct path is generic.

Those configure `OpenCodeClient`, which serves `/v1/chat/completions`, `/api/v1/chat/completions`, and `/api/v1/opencode/chat/completions` (`main.rs:1484-1525, 1772`), not the answer path. ### Workstream D: Tailwind scan, sidebar tokens, shadcn dialogs

**Root cause A, proven.** `globals.css` has no `@source`, and Tailwind v4 detects sources from the Vite root, so `packages/ui` classes are never scanned. The shipped `index-BkpD1pmg.css` contains zero `position:fixed`, `.z-50`, `.max-w-lg`, `pointer-events-none`, or dark-surface classes. The wrapper keeps only `inset-0` and `flex` and becomes a flex item of the root row at `CommandCenterLayout.tsx:123`. That is the screenshot.

**Root cause B, missed by the source plan.** Sidebar utilities cannot exist at all. `avrig-ui/packages/tokens/theme.css:3-22` registers `--color-background` through `--color-ring`, and the `--sidebar-*` values at `:57-63` are plain CSS variables, which Tailwind does not turn into utilities. `border-sidebar-border` and `bg-sidebar-background` are therefore ungeneratable, and the sidebar has been unstyled all along.

**Fix A.** Add `@source` plus the animation import in the three entries:

| Entry | Directive |
| :--- | :--- |
| `apps/web/src/styles/globals.css` | `@source "../../../../packages/ui/src";` |
| `apps/mobile/src/styles/globals.css` | same |
| `apps/desktop/src/index.css` | `@source "../../../packages/ui/src";` |

A wrong path fails silently, so the only proof is grepping emitted CSS after a real build.

**Fix B.** Register the sidebar tokens in `avrig-ui/packages/tokens/theme.css` inside `@theme inline`: `--color-sidebar-background`, `--color-sidebar-foreground`, `--color-sidebar-primary`, `--color-sidebar-primary-foreground`, `--color-sidebar-accent`, `--color-sidebar-accent-foreground`, `--color-sidebar-border`, `--color-sidebar-ring`, each pointing at the existing raw variables. ### Release mechanics

**Ordering, corrected.** Version and dirty state are compile-time inputs, so naming has to come after building:

```text
commit implementation in all four repos (including build.rs and dist)
-> bump and commit
-> build
-> deploy
-> verify live
-> release.ps1 0.3.0 -SkipBump -NoPush   (tags HEAD, nothing staged)
-> push branch and tag to all four remotes
-> verify remote heads and tags
```

Bump-only work uses `make bump-minor` in `avrig-ai` plus `make check-version-sync`, then a commit. `release.ps1 -SkipBump` exists at `:11,52-57` and tags HEAD when nothing is staged (`:157-159`), which is exactly the final step.

Before tagging, require a completely clean tree in all four repos, because `release.ps1:142` runs `git add -A` and would sweep unrelated working-tree edits into the release commit.

**Version sources**, all three at `0.3.0`: `avrig-ai/Cargo.toml:12`, `avrig-ai/apps/web/package.json:3`, `avrig-api/Cargo.toml:3`. Both `Cargo.lock` files refresh.

**Guard hardening.** Staged-diff scanning only, and it skips scanning when a repo has nothing staged, which is the expected state for `avrig-lib` and `avrig-ui`. Add a range mode that scans `git log -p <tag>~1..<tag>` and run it after the push. Extend `secretPatterns` with `ATATT3x[A-Za-z0-9_-]{20,}`, `GOCSPX-[A-Za-z0-9_-]{20,}`, `1071006060591-[a-z0-9]{6,}`, `sk-[A-Za-z0-9]{20,}`, `ghp_[A-Za-z0-9]{30,}`, `xox[baprs]-[A-Za-z0-9-]{10,}`, `-----BEGIN [A-Z ]*PRIVATE KEY`, and staged paths matching `(^|/)\.env$`, `(^|/)confluence\.env$`, `\.pem$`, `\.p12$`. Assert `apps/*/dist/`, `target/`, `node_modules/` never appear in a staged path, and that a tracked `scripts/*.sh` carries no assignment matching `(SECRET|TOKEN|PASSWORD)=["'][^"']{12,}`.

**Credential remediation.** `scripts/test_ingest.sh:4` holds a live `CLIENT_SECRET`, tracked since `4ca5a09`. Remove it, take it from the environment, rotate the `avrig-watcher` client secret in Rauthy, update `/etc/avrig/avrig.env` and the NSSM environment, and treat the old value as compromised. History rewrite is out of scope for this release; record the exposure instead.

## Execution Runbook

The section above says what runs in parallel. This section says how to run it: who is dispatched, with which constraints, what each stream must not touch, and where the commit and gate boundaries sit. Read the workstream design for detail; this is the operating sequence.

### Gate and checkpoint spine

```text
P-1  credential remediation        gate G1
P0   analyst re-audit              gate G2
P1-P11 implementation streams      checkpoint CK2, clean trees
P12  commit everything             checkpoint CK3
P13  bump and commit               checkpoint CK4, clean trees
P14  build                         checkpoint CK5, captured SHAs
P15  deploy                        gate G3
P16  verify                        gate G4
P17  tag HEAD and push             checkpoint CK6, remote parity
P18  archive and lesson            gate G5
```

No stream starts before G2 passes. No tag is created before G4 passes. No push happens before the guard runs in range mode against the local tag.

### P-1 Credential remediation

Independent of the release, and it runs first because the value is already on a remote.

`be` edits `avrig-api/scripts/test_ingest.sh`:

1. Delete the `CLIENT_SECRET="..."` assignment at line 4.
2. Read the secret from the environment and fail fast when unset: `: "${CLIENT_SECRET:?CLIENT_SECRET must be set}"`.
3. Keep the rest of the script behaviour unchanged, still targeting `/api/v1/knowledge/search` per P3.
4. Commit the script on its own, so the removal is visible in history.

`Infra` rotates the credential:

1. In Rauthy, rotate the client secret for the `avrig-watcher` client.
2. Update `/etc/avrig/avrig.env` and the NSSM `AppEnvironmentExtra` for the Windows service with the new value.
3. Restart `avrig.service` and the Windows service.
4. Verify the watcher still authenticates, and that a request with the old secret now returns `401`.

Exit criteria for G1: no tracked file contains a literal secret, rotation verified on both nodes, and the exposure recorded in the release risk table. History rewrite stays out of scope and stays recorded as an accepted risk.

### Commit strategy

Checkpoint CK2, after P1 to P11 land, all four repositories:

```powershell
git -C avrig-api add -A; git -C avrig-api commit -m "feat(search): single knowledge endpoint on opencode/big-pickle"
git -C avrig-lib add -A; git -C avrig-lib commit -m "fix(gateway): log stream dispatch"
git -C avrig-ui  add -A; git -C avrig-ui  commit -m "fix(tokens): register sidebar color tokens"
git -C avrig-ai  add -A; git -C avrig-ai  commit -m "feat(ui): scss scan, shadcn dialogs, iam chip parity"
```

Include `avrig-api/build.rs` and both `dist` trees in CK2. Then prove all four trees are empty before CK3, because `release.ps1` uses `git add -A` and would otherwise absorb unrelated edits.

CK3, the bump:

```powershell
cd avrig-ai; make bump-minor; make check-version-sync
git -C avrig-ai  commit -am "chore(release): 0.3.0"
git -C avrig-api commit -am "chore(release): 0.3.0"
```

If `make bump-minor` also touches `avrig-lib` or `avrig-ui` manifests, commit those two at the same checkpoint.

CK4 is the cleanliness gate: `git status --porcelain` empty in all four repos. If anything remains, stop and commit it rather than letting the tag capture it.

### Build and deploy notes

P14 builds in this order: `pnpm --filter @avrig/ui build`, `pnpm --filter @avrig/api-client build`, `pnpm build`, `cargo test` for `avrig` and `avrig-gateway`, then `make build`. Capture `sha256sum` of both binaries and the reported `commit_short_sha` before deploying, so V2 and V3 compare an artifact rather than a hope.

P15 deploys with `make deploy`, then runs `update-theme` with the fixed skill path. Confirm before moving on: Windows `server.toml` exists with a loopback host, `/opt/avrig/config/server.toml` still binds `127.0.0.1`, and the theme cache-bust moved.

### Stop conditions

Stop and escalate instead of improvising when any of these appear:

1. `git status` is not empty at CK3 or CK4.
2. A build reports `dirty: true` after CK4.
3. The emitted CSS lacks `position:fixed` or `.border-sidebar-border` after P14, which means a scan or token fix did not take.
4. `/api/v1/version` and `/api/v1/health` disagree on the build object.
5. A tombstoned path returns anything other than `410`.
6. The guard finds any secret match in range mode, including a rotated value still in history.
7. The watcher fails to authenticate after rotation, which means P-1 was not actually completed.

### Rollback points

| Checkpoint | Rollback |
| :--- | :--- |
| CK2 or CK3 | `git reset --hard` to the pre-release commit in each repo, no deployment happened yet |

| All V rows pass but a regression appears later | revert the specific commit and run P14 to P16 again; the tag stays, and the next patch release supersedes it |
