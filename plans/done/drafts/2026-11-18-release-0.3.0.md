# Release 0.3.0: Composync, Typed Model Errors, Build Metadata, UI Fixes

Status: superseded by 2026-11-18-release-0.3.0-consolidated.md
Owner: build (orchestration), tester (verification), Infra (deploy), analyst (goal audit)
Created: 2026-11-18

## Goals and Objectives

1. Ship the accumulated work as **0.3.0** (minor, new backward-compatible capability) across all four repositories: `avrig-ai`, `avrig-api`, `avrig-lib`, `avrig-ui`.
2. Content of the release:
   - `composync` registered as a gateway provider, reachable from the `LocalSystem` service and from `avrig.service`.
   - Typed model resolution errors: unknown prefix and unknown sub-model both return `404 model_not_found`; upstream unknown-model faults map to 404; unrelated 400s stay 502.
   - Request tracing with provider, requested model, resolved upstream model, upstream status, and elapsed milliseconds, at both the library and the handler layer.
   - `/api/v1/health` carries `version`, `semver`, and a `build` object; `avrig --verbose-version` exists and prints real build metadata, backed by a new `avrig-api/build.rs`.
   - Rauthy login language selector matches the landing page chip.
   - Dialog modals rebuilt on shadcn/ui with working overlay, centering, focus, and Escape.
3. Binaries deployed from this release must report `0.3.0` with `dirty: false` on both Windows and WSL. The 0.2.0 and 0.2.1 releases both shipped binaries stamped `dirty: true`, built from a tree that did not match the tag. This plan inverts the order so it cannot happen again: prove the build first, then tag and publish.
4. Every tag must exist on all four remotes at a commit whose tree matches the deployed artifacts.
5. All test suites pass before the bump: `avrig-gateway` 42, `avrig` bin unit tests, gateway integration tests, the composync probe set, and the two UI matrices from the sibling plans.

## Key Detailed Design

### Program Design

Ordering rule, which is the core of this plan:

```
implement -> build -> deploy -> verify live -> bump -> tag -> push -> verify remotes
```

The release script supports this without modification: `scripts/release.ps1 minor -NoPush` performs the bump, lockfile refresh, per-repo commit, and annotated tag locally while skipping the push.

Version sources, all three must agree:

| File | Field | From | To |
|---|---|---|---|
| `avrig-ai/Cargo.toml` | `[workspace.package] version` (canonical) | `0.2.1` | `0.3.0` |
| `avrig-ai/apps/web/package.json` | `version` | `0.2.1` | `0.3.0` |
| `avrig-api/Cargo.toml` | `version` | `0.2.1` | `0.3.0` |

Both `Cargo.lock` files refresh as a side effect; `avrig-api/build.rs` reads `CARGO_PKG_VERSION` through the usual cargo env, so no extra wiring is needed for the version string, only for the git metadata.

Credential guard, to extend before this run. The 0.2.0 push was rejected twice by GitHub push protection. The current guard in `release.ps1` matches a pattern list against the staged diff, but the OAuth literals were neutralised by splitting them across lines, which means a naive contiguous match would now pass while the concatenated value still exists. Extend `secretPatterns` with:

- `ATATT3x[A-Za-z0-9_-]{20,}` (Atlassian)
- `GOCSPX-[A-Za-z0-9_-]{20,}`
- `1071006060591-[a-z0-9]{6,}` (Google OAuth client id prefix)
- `sk-[A-Za-z0-9]{20,}`, `ghp_[A-Za-z0-9]{30,}`, `xox[baprs]-[A-Za-z0-9-]{10,}`
- `-----BEGIN [A-Z ]*PRIVATE KEY`
- staged paths matching `(^|/)\.env$`, `(^|/)confluence\.env$`, `\.pem$`, `\.p12$`

Also assert that `apps/*/dist/`, `target/`, and `node_modules/` appear in no staged path list, since the 0.2.0 commit carried `apps/desktop/dist/` and `apps/mobile/dist/`.

Repositories and branches:

| Repo | Branch | Release content |
|---|---|---|
| `avrig-ai` | `feat/avatar-first-development` | theme CSS, skill path fix, web/mobile/desktop CSS entry, `packages/ui` Dialog and AlertDialog, `components.json`, version manifests |
| `avrig-api` | `main` | `build.rs`, health payload, `--verbose-version`, error mapping, integration tests, `Cargo.toml` |
| `avrig-lib` | `main` | resolver variants, catalogue cache, tracing, dispatch validation |
| `avrig-ui` | `main` | tag only at current HEAD unless the shadcn sources are also synced here |

`avrig-ui` deserves an explicit decision: the plan for the dialog ports upstream shadcn source into `avrig-ai/packages/ui`, while `avrig-ui/packages/ui` holds an older Radix variant. Either sync `avrig-ui` to the same source in this release, or tag it at HEAD with no code change and record why. Do not leave the two copies silently divergent without a note.

Deployment after tagging:

1. `pnpm --filter @avrig/ui build` then `pnpm build` in `avrig-ai` for fresh `apps/*/dist`.
2. `make build` in `avrig-api` (frontend dist, Windows PE, Linux ELF in WSL `avrig-ai`).
3. `make deploy` (stops the Windows service, hash-verifies, copies to `D:\avrig\` and `/opt/avrig/`, restarts both, syncs `gateway.toml`).
4. Confirm `--verbose-version` reports `0.3.0` and `dirty: false` on both targets, `/api/v1/version` returns `0.3.0`, and `/api/v1/health` returns the same with the build object.

Runner notes: `curl.exe` needs `--ssl-no-revoke` on this host (Schannel cannot reach a CRL server). `localhost:8000` is answered by the WSL instance through `wslrelay.exe`; the Windows instance is reachable at `127.0.0.2:8000` and rejects non-loopback clients by design. `avrig --verbose-version` exits before config load, so it is safe to call while the service runs.
