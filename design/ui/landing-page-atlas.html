03 / Authority and artifact state

Intelligence is not authority.

Agents may analyze, synthesize, recommend, plan, draft, and execute within permitted boundaries. Human decisions and formal artifact approvals remain distinct, recorded acts.

AUTHORITY / HUMAN

Founder

Owns consequential decisions, approvals, policy, and baselines.

ACTIVITY / AGENT

Analyze and execute

Agents work through typed capabilities and governed tool boundaries. They cannot approve their own output or silently override a human decision.

DECISION RECORD

Decide

Adopt, modify, reject, defer, or request revision, with rationale and evidence.

ARTIFACT GATE

Baseline

Formal approval establishes an authoritative, versioned outcome for downstream stages.

Epistemic statusAuthoritative Requirement · Approved Baseline · Existing Practice · Best Practice · Agent Inference · Assumption or Unknown
Artifact statesDraft → Candidate → Validated Candidate → Reviewed Candidate → Approved, Superseded, or Rejected
TraceabilityLinks connect specific source and target versions through named relations, not vague artifact associations.
04 / Knowledge and evidence

05 / Technology architecture

One product across work surfaces.

The technology definition separates user clients, the Rust service, governed agent capabilities, and authoritative persistence. The diagram summarizes the approved stack, not a live infrastructure status page.

Web & native shells

React and TypeScript workspace. Browser delivery, Tauri desktop shell, and Capacitor mobile package share the client foundation.

02 / SERVICE

Office + SDLC

Rust service with Axum and Tokio. Typed HTTP surfaces and event streams connect client interactions with domain operations.

03 / HARNESS

Governed agents

Knowledge, context, skills, policy, events, traceability, provider adapters, and sandboxed tool execution.

04 / RECORDS

State + graph

PostgreSQL for relational records and pgvector. Apache AGE for graph traversal. S3-compatible object storage for artifacts.

Models + retrieval

Provider abstraction, local embedding and reranking capabilities, hybrid retrieval, and stage-scoped context assembly.

06 / The virtual organization

Identity persists. Runtime comes and goes.

The Founder owns the organization. The CEO/PET operates it. The Personal Assistant is a separate role serving the Founder. Persistent employee identities participate across departments and project teams.

Founderhuman owner and final authority
Personal Assistantdirect support to Founder
CEO / PETAI Employee 001, company operations
Executivescompany-wide functional leadership
Department headsdiscipline and workforce leadership
Project teamscross-functional delivery assignments

Department membership and project assignment are orthogonal. An employee has a home department and may also work on one or more project teams.

Employee identity holds persistent history, skills, memory, and relationships. Agent runtime is the temporary execution process, with its own working context and telemetry. Ending a runtime does not erase the employee.

The Office Operating System can also project organizational state into a spatial 3D office. The projection is a visualization; structured organizational records remain authoritative.
