# Human Decision & Approval

## 1. Purpose

Human Decision & Approval is a cross-cutting AGENTIC capability that ensures recommendations, analyses, proposals, and other Agent-generated outcomes do not become authoritative merely because they were generated by an Agent.

The fundamental principle is:

> **Agent recommends. Human decides.**

The capability provides a controlled mechanism for a human to review an Agent recommendation, make a decision, and record the decision and its rationale.

## 2. Scope

Human Decision & Approval applies across the AGENTIC engineering lifecycle whenever an Agent produces a recommendation, proposal, candidate solution, analysis, or other outcome that requires human authority.

It is not limited to a single lifecycle stage.

Typical examples include:

- Vision recommendations
- Mission proposals
- Strategy alternatives
- Business capability proposals
- Business process designs
- Activity definitions
- Role definitions
- User stories
- UI/UX approaches
- Data model alternatives
- NFR recommendations
- Architecture decisions
- Technology selections
- Development or implementation recommendations
- Test or deployment decisions

## 3. Core Principle

The Agent may:

- Analyze
- Recommend
- Explain
- Compare alternatives
- Identify risks
- Identify assumptions
- Provide evidence
- Propose changes

The human remains the decision authority.

The Agent must not interpret its own recommendation as approved unless an explicit human decision has been recorded.

## 4. Decision Model

The standard decision flow is:

```text
Agent Analysis / Recommendation
            |
            v
      Human Review
            |
            v
      Human Decision
     +------+------+--------+---------+
     |      |      |        |         |
     v      v      v        v         v
   Adopt  Modify  Reject   Defer   Request Revision
     |      |      |        |         |
     +------+------+--------+---------+
            |
            v
      Decision Recorded
            |
            v
   Authoritative Outcome
   or Further Iteration
```

## 5. Human Decision Types

### 5.1 Adopt

The human accepts the Agent recommendation substantially as proposed.

The recommendation may become an authoritative project outcome after the applicable approval and governance requirements are satisfied.

### 5.2 Modify

The human accepts the recommendation with explicit modifications.

The modified result, rather than the original Agent recommendation, becomes the candidate outcome for further processing or approval.

### 5.3 Reject

The human explicitly decides not to adopt the recommendation.

A rejected recommendation must not become authoritative project knowledge or an approved lifecycle artifact.

The rejection and rationale should be retained when useful for traceability and future analysis.

### 5.4 Defer

The human postpones the decision because additional information, analysis, stakeholder input, or another dependency is required.

A deferred recommendation remains non-authoritative.

### 5.5 Request Revision

The human asks the Agent to reconsider the recommendation and produce a revised recommendation.

This creates an iterative Agent-human refinement loop.

```text
Agent Recommendation
        |
        v
   Human Review
        |
        +---- Request Revision
        |          |
        |          v
        |    Agent Re-analysis
        |          |
        |          +----> New Recommendation
        |
        +---- Adopt / Modify / Reject / Defer
```

## 6. Recommendation Review Context

Before making a decision, the human should be able to understand why the Agent produced the recommendation.

The Agent should provide, where applicable:

- Recommendation
- Alternatives considered
- Rationale
- Supporting evidence
- Source information
- Applicable requirements
- Applicable Project Knowledge
- Applicable Platform Knowledge
- Assumptions
- Constraints
- Risks
- Dependencies
- Conflicts or ambiguities
- Agent inference
- Confidence or uncertainty
- Potential impact

The Agent must distinguish between:

- **Requirement**
- **Existing Practice**
- **Best Practice**
- **Agent Inference**
- **Unknown / Ambiguous**

This distinction prevents inferred conclusions from being presented as established facts.

## 7. Decision Record

Each material human decision should be recorded with sufficient information to establish traceability.

Recommended structure:

| Field | Description |
|---|---|
| Decision ID | Unique identifier |
| Subject | Item or recommendation being decided |
| Agent Recommendation | Recommendation presented to the human |
| Alternatives | Alternatives considered, where applicable |
| Decision | Adopt, Modify, Reject, Defer, or Request Revision |
| Final Decision | Human-approved outcome, if applicable |
| Rationale | Reason for the human decision |
| Evidence | Evidence considered |
| Decision Maker | Human responsible for the decision |
| Date/Time | Time of decision |
| Related Requirement | Requirement or business context |
| Related Artifact | Lifecycle artifact affected by the decision |
| Dependencies | Relevant dependencies |
| Risks | Relevant risks |
| Status | Current decision status |
| Version | Version of the recommendation or artifact |
| Supersedes | Previous decision, if applicable |

## 8. Authority Rules

The following rules apply:

1. Agent-generated content is **non-authoritative by default**.
2. Human decisions establish whether a recommendation is adopted.
3. An Agent cannot approve its own recommendation.
4. An Agent cannot silently override a human decision.
5. A human modification takes precedence over the original Agent recommendation.
6. Rejected recommendations must not be treated as approved requirements or design decisions.
7. Deferred recommendations remain unresolved until a subsequent decision is recorded.
8. Material decisions should remain traceable to the recommendation, evidence, and resulting artifact.
9. When a decision conflicts with existing Project Knowledge or approved artifacts, the conflict must be surfaced rather than silently resolved by the Agent.
10. The human remains the final authority for decisions requiring human approval.

## 9. Relationship with Project Knowledge

Only information that has been explicitly adopted through the applicable human decision and governance process may become authoritative Project Knowledge.

The general flow is:

```text
Agent Recommendation
        |
        v
Human Decision
        |
        +---- Reject / Defer
        |        |
        |        v
        |   Non-authoritative
        |
        +---- Adopt / Modify
                 |
                 v
        Approved Outcome
                 |
                 v
        Project Knowledge
```

Project-specific knowledge remains authoritative over generic Platform Knowledge when the two conflict.

## 10. Relationship with Platform Knowledge

A project outcome should not automatically become Platform Knowledge.

Where an adopted project decision contains reusable knowledge, it may later be considered for promotion to Platform Knowledge through an explicit generalization and governance process.

```text
Project Decision
      |
      v
Generalization
      |
      v
Review / Governance
      |
      v
Platform Knowledge Candidate
      |
      v
Human Approval
      |
      v
Platform Knowledge
```

This prevents project-specific assumptions from being unintentionally generalized into reusable engineering guidance.

## 12. Agentic Engineering Principle

As AGENTIC becomes more autonomous, the Agent may perform increasingly sophisticated analysis and generate increasingly complete recommendations.

However, greater Agent autonomy does not imply automatic authority.

The distinction is:

> **Autonomy determines what the Agent can do. Authority determines what the Agent is allowed to decide.**

AGENTIC therefore separates:

- Agent execution
- Agent recommendation
- Human decision
- Approval
- Authoritative project state

This separation allows AGENTIC to increase automation while preserving human control over consequential engineering decisions.

## 13. Boundary with Approval and Governance

Human Decision & Approval records the human decision regarding an Agent recommendation.

Formal lifecycle approval and governance remain responsible for establishing the authoritative status of lifecycle artifacts, baselines, versions, and controlled changes.

Therefore:

- **Human Decision** answers: *What does the human decide about the recommendation?*
- **Approval** answers: *Is the resulting artifact formally approved?*
- **Governance** answers: *How is the approved artifact controlled, versioned, changed, and maintained?*

These concepts are related but should not be collapsed into a single mechanism.

## 14. Key Principle

> **The Agent provides intelligence and recommendations. The human provides authority.**

This principle applies across all AGENTIC lifecycle stages and becomes increasingly important as the platform progresses toward higher generations of agentic engineering capability.
