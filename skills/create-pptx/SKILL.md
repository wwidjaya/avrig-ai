# Create PowerPoint Reports

Create clear, editable strategy, implementation, and technical-report decks. Match the supplied template and brand. Do not imply endorsement by organizations whose marks appear in references.

## Workflow

1. **Collect locations in order.** Start by asking for the Markdown content (`.md`) file location. After the user provides it, read it to understand the context before asking for the PowerPoint template (`.pptx` or `.potx`) location. After receiving and inspecting the template, ask for the output folder. Ask one question at a time and wait for each answer. Reuse a location already explicitly provided for this deck. Refer to the destination as the “output folder”; do not call it a test deck or test PPTX. If no template is available, ask whether to proceed without one before designing.
2. **Understand the content and template.** Read the source as read-only. Extract claims, figures, dates, definitions, units, caveats, and citations; flag gaps instead of inventing facts. Inspect the rendered title slide first, then representative content, section, chart/table, diagram, and appendix slides. Record the template’s dimensions, typography, colors, grid, logos, and image treatment.
3. **Confirm the cover direction.** Offer the user a choice between keeping the template’s title-slide layout and redesigning it. If they keep the template, preserve its layout. If they want a redesign, propose a few distinct layout options informed by the template and content; ask which option to use and wait for confirmation before implementing it. Implement the selected layout when feasible. For the editorial cover, use a light text column on the left, a cropped image on the right, template marks at the top, and restrained typography. Then propose a concise title and optional subtitle that fit the selected layout; get approval unless the user already supplied the wording. Ask whether to keep or replace the template’s existing background image. For a replacement, or an empty image placeholder, present concrete design ideas and the full image-generation prompt, including subject, mood, composition, crop, and text-safe space. Keep cover imagery religiously neutral unless the content explicitly calls for religious subject matter; avoid religious clothing, symbols, and worship settings. Wait for explicit approval of that design before generating; a general request to create an image or approval of an earlier image is not approval of a new design. If the user supplies a ready-to-use image and asks to use it, do not generate another. If the user asks for an artistic photo treatment, show a few concrete treatments (for example, circle with halo, angled layered crop, or soft frame) and wait for their selection. Keep the approved photo editable and start each treatment from the clean cover so crops and frames do not accumulate. If the user returns to the original template, rebuild from the untouched template and approved image rather than layering changes onto a treated cover. Keep an intentionally image-free cover free of decorative imagery.
4. **Plan the story and design.** State the deck’s purpose, then map each slide to its purpose, title, key message, evidence or visual, source, and transition. Follow the template’s layouts and visual rules. Without a template, use a restrained institutional style: light canvas, strong contrast, consistent grid, limited accents, readable typography, and purposeful diagrams.
5. **Build a reusable template cover.** For a standalone one-slide cover, use `create_cover_pptx.py` in this skill folder (standard-library Python; it is not `python-pptx`). Pass the approved cover image, template, output path, and repeat `--replace "OLD=NEW"` for text edits. Example:
   ```powershell
   python "<skill-folder>\create_cover_pptx.py" --template "<template.pptx>" --cover-image "<approved-cover.png>" --output "<output-folder>\cover.pptx" --overlay-color "#002C36" --overlay-transparency 55 --overlay-width 1.0 --replace "Old title=New title"
   python "<skill-folder>\validate_cover_pptx.py" "<output-folder>\cover.pptx"
   ```
   The builder fits the image to the slide, adds a separate editable overlay, and retains the template package. For an approved editorial redesign, run `create_editorial_cover.py` on the one-slide cover to create a white text column and framed image, preserving editable text and logos. For a selected artistic image treatment, run `style_cover_photo.py` on a clean one-slide cover; choose `circle-halo`, `angled-layer`, or `soft-frame`. Example: `python "<skill-folder>\\style_cover_photo.py" --input "<build-folder>\\cover-base.pptx" --output "<output-folder>\\cover-styled.pptx" --style circle-halo`. Both tools make surgical XML edits to preserve the template's namespace and extension markup. Override shape IDs when needed. The photo stays unlocked, and the source remains unchanged. These scripts create cover slides only; use the full-deck workflow below for multi-slide presentations.
6. **Build a full deck.** Follow the installed Presentations skill and its supported `@oai/artifact-tool` workflow; do not author with `python-pptx`. Prefer editable PowerPoint text, shapes, charts, tables, and diagrams. Preserve requested evidence and add source notes where needed. Keep private build files separate from final deliverables; save finals in the requested output folder with new filenames.
7. **Handle cover images safely.** For the template’s original full-bleed design, fit the approved image to the slide canvas and keep it separate from any overlay. If adding an overlay rectangle, make it full-slide and editable; do not bake it into the image. For an artistic crop, use the original approved image, keep the picture unlocked, and make any backing shape a separate editable object. Leave the background and overlay unlocked, selectable, movable, and resizable.
8. **Render, inspect, and repair.** Render every slide, inspect a contact sheet and each slide at full size, and check narrative flow, alignment, contrast, text fit, readability, charts, tables, citations, and template consistency. Run package and layout checks. Repair issues and rerender affected slides. Structural checks do not replace visual inspection. Say clearly if native PowerPoint verification was unavailable.
9. **Deliver.** The filename must begin with the user-local date in `YYYY.MM.DD` format, followed by the descriptive name and semantic version: `YYYY.MM.DD <Descriptive name> vMAJOR.MINOR.PATCH.pptx`. Use the source version when available; otherwise start at `v1.0.0`, unless the user specifies a version. Save in the requested output folder without overwriting prior files. Provide requested companion files and mention material assumptions or validation limits; exclude temporary build files.

## Quality rules

- Give each slide one job and a direct title. Put the main finding before supporting details; distinguish facts from interpretation and recommendations.
- Keep terminology, units, dates, citations, bilingual wording, logos, and visual conventions consistent.
- Use native editable charts for data comparisons and editable tables when readers need to reuse values. Label units, periods, sources, axes, and denominators. Simplify crowded slides or split them instead of making text too small.
- Keep text within safe margins. Check for clipping, overlap, orphaned labels, unsupported glyphs, broken assets, and unintended off-slide objects.
- Use images only when they add context or are required. Preserve supplied logos and artwork, including proportions.
